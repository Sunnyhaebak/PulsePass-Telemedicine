📐 Production Architecture & Engineering Blueprint

Full technical deep-dive into Concurrency Locks, S3 Vault, and WebSocket Session Guards.

1. Distributed Slot-Locking Mechanism (Zero Double-Booking Guarantee)

When two patients click the same slot at the exact same millisecond, standard SQL queries without locks cause race conditions. Our backend acquires a Redis distributed lock (SET lock:slot:{slot_id} {uuid} NX PX 5000) before executing a PostgreSQL row-locked transaction (SELECT ... FOR UPDATE).

// Redis Distributed Lock + PostgreSQL Row-Lock Transaction (NestJS Service) async bookSlot(slotId: string, patientId: string, passId: string) { const lockKey = `lock:slot:${slotId}`; const lockAcquired = await this.redis.set(lockKey, patientId, 'PX', 5000, 'NX'); if (!lockAcquired) { throw new ConflictException('Slot is currently locked by a concurrent booking transaction'); } try { return await this.prisma.$transaction(async (tx) => { const slot = await tx.$queryRaw`SELECT * FROM time_slots WHERE id = ${slotId} FOR UPDATE`; if (slot.status !== 'AVAILABLE') throw new BadRequestException('Slot already taken'); return tx.timeSlot.update({ where: { id: slotId }, data: { status: 'BOOKED', patientId, passId } }); }); } finally { // Release Redis lock safely via Lua script await this.redis.eval(UNLOCK_SCRIPT, 1, lockKey, patientId); } }

2. Zero-Exposure Medical File Pipeline (AWS S3 Pre-Signed URLs)

Medical files (Blood panels, ECGs, X-rays) never traverse the Node.js server memory or reside in public buckets. The backend validates RBAC permissions and generates a 5-minute pre-signed PutObject URL for upload and a 10-minute GetObject URL for the assigned doctor.

// S3 Zero-Exposure Pre-Signed URL Pipeline async generateUploadUrl(patientId: string, passId: string, fileName: string) { // Validate active 7-day pass await this.passGuard.validateActivePass(patientId, passId); const objectKey = `vault/${patientId}/${crypto.randomUUID()}-${fileName}`; const presignedUrl = await getSignedUrl(this.s3Client, new PutObjectCommand({ Bucket: process.env.MEDICAL_VAULT_BUCKET, Key: objectKey, ServerSideEncryption: 'AES256', }), { expiresIn: 300 }); // 5 minutes TTL return { uploadUrl: presignedUrl, objectKey }; }

3. WebSocket Gateway Session & Pass Expiry Enforcement

Every incoming WebSocket message checks a Redis-cached pass TTL (pass:active:{pass_id}). Expired passes are locked at the gateway layer without incurring database load.

@SubscribeMessage('sendMessage') async handleMessage(@ConnectedSocket() client: Socket, @MessageBody() dto: SendMessageDto) { const isPassActive = await this.redis.get(`pass:active:${dto.passId}`); if (!isPassActive) { client.emit('passExpiredError', { message: '7-Day Pass expired. Renew to message doctor.' }); return; } const savedMsg = await this.chatService.saveMessage(dto); this.server.to(`pass_${dto.passId}`).emit('newMessage', savedMsg); }
